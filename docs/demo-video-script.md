# Demo 视频脚本 / 分镜（Novel2Script）

> 目标时长：**≤ 3 分钟**。录制模式：**离线 fixture 模式**（无需 API Key，最稳，评委可零配置复现）。
> 题目三要求的全过程都要出现：**输入 → 解析 → 生成 → 溯源 → 编辑 → 校验**，并突出"可追溯、可校验、非套壳"的工程亮点。

---

## 0. 录制前准备（Checklist）

- [ ] 终端：项目根目录运行 `npm run dev`，浏览器打开 `http://localhost:3000`。
- [ ] **确认离线模式**：不要设置 `OPENAI_API_KEY`（或在 `.env.local` 设 `DEMO_MODE=fixture`）。解析后右上角应显示 **"离线 Demo"** 徽章。
- [ ] 浏览器窗口 ~1440×900，缩放 100–110%，保证 YAML 文本清晰可读。
- [ ] 开局状态：原文框为空、各面板为"尚无…"。
- [ ] 预演一遍"编辑→重新校验"那步，记住把哪个 `source_refs` 的 ID 改坏（见镜头 7）。
- [ ] 旁白可后期配音；若现场口播，按下方"旁白"逐句读。
- [ ] 备一张终端截图：`npm test` → **124 passed**（镜头 9 用）。
- 说明：当前 UI 没有"下载导出"按钮——**YAML 编辑器本身就是可编辑、可取走的初稿**（全选复制即可）。镜头 8 以"复制 YAML"呈现"导出"。

## 2. 连续旁白稿（口播版，约 2'50"）

> 录屏时按操作节奏读，可后期配音。

"这是 Novel2Script——把小说自动转成**结构化、可校验、可追溯**的剧本 YAML。它不是把小说丢给模型自由发挥：每一句台词都能回指原文，每条引用和短剧约束都由程序检查。

先**载入内置的原创三章小说**——雾港旧码头、沉船旧案，主角林深。你也可以粘贴自己的三章以上文本。

点**解析**。这一步**纯代码、不依赖 AI**：切分章节段落，给每段生成**稳定 ID**，同一段文本永远是同一个 ID；整篇还有一个**指纹**，用来防伪造。

点**分析**，抽取人物和地点——注意 **ID 由系统按名字确定性生成**，不让模型乱编。点**规划**，改编成 3 集短剧，每集有钩子和悬念。

点**生成**。出来的是结构化 YAML：集、场景、有序的 beats。关键在这——**每句对白都带 source_refs，指回原文段落**；右边的质量报告由程序算出：**原文覆盖率 100%**、引用数、有没有没溯源的场景。

剧本是**可编辑**的。我故意把一个引用改成不存在的 ID，点**重新校验**——它**不相信模型、只认校验**，立刻报错，并给出**精确到这条引用的路径**。改回去再校验，通过。

通过的 YAML 就是可取走、可继续打磨的剧本初稿。背后是确定性内核加多阶段 pipeline，配套 Schema 设计文档和 124 个测试；配上 OpenAI 兼容 Key，就能把**任意**小说转成同样可校验的剧本。"

## 3. 必须出现的"证据点"（验收对照）

- [ ] 稳定段落 ID（如 `ch1_p1_df6f5806`）+ 整篇**指纹**徽章 → 可追溯/防伪造
- [ ] 人物/地点**确定性 ID**（如 `char_aadd69`）→ 引用稳定
- [ ] YAML 里的 **`source_refs`** 指回段落 → 可追溯
- [ ] **质量报告**（覆盖率/引用/无溯源场景）= 程序计算 → 可量化
- [ ] **编辑后重新校验 → 精确路径错误**（`INVALID_SOURCE_REF` + `episodes[…].source_refs[…]`）→ 可校验、非套壳
- [ ] 校验通过 → 可编辑的剧本初稿
- [ ] （加分）Schema 文档 + 124 测试 + live 模式一句话
