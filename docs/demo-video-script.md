# Demo 视频脚本 / 分镜（Novel2Script）

> 目标时长：**≤ 3 分钟**（主体流程）+ 可选 **+40 秒** live 并行生成进度补拍。
> 录制建议：**主体用离线 fixture 模式**（确定性、即时、零配置，评委可复现），最后**可选切到 live 模式**补拍"按集并行生成进度"这一新亮点。
> 题目要求的全过程都要出现：**输入 → 解析 → 分析 → 规划 → 生成 → 追溯 → 编辑 → 校验 → 导出**，并突出"可追溯、可校验、可编辑"的工程亮点。

---

## 0. 开始前准备（Checklist）

- [ ] 终端：项目根运行 `npm run dev`，浏览器开 `http://localhost:3000`。
- [ ] **确认离线模式**：`.env.local` 里设 `DEMO_MODE=fixture`（或干脆不配 `OPENAI_API_KEY`）。解析后右上角应显示 **"离线 Demo"** 徽章 + **指纹 `68d7c2e2e2ec7e59`**（绿色，表示内置 Demo 可离线生成）。
- [ ] 浏览器窗口 ~1440×900，缩放 100–110%，保证 YAML 与卡片清晰；UI 是三栏：**左 Pipeline 导航 / 中 Stage 工作区 / 右 Inspector 检查器**。
- [ ] 开局状态：原文框为空、左栏各步骤为"未运行 / idle"。
- [ ] 预演一遍"编辑→校验报错"那步：把某个 `source_refs` 的 ID 改成 `ch9_p9_zzzzzzzz`（见镜头 8）。
- [ ] 旁白可配音可静音；分屏录终端 `npm test` → **168 passed**（镜头 9）。
- [ ] （如要补拍 live 段）准备好一段 ≥3 章自有小说文本，并按第 4 节切换环境。

## 2. 连续旁白稿（口播用，约 2'50"）

> 当屏时无操作旁白，可减少停顿。

"这是 Novel2Script——把小说自动转成**结构化、可校验、可追溯**的剧本 YAML。模型只做改编创意，它的产出必须先通过**代码校验闸门**，才会变成 YAML，所以每一句台词都能回指原文。

先**载入内置的原创三章小说**《雾港旧约》。你也可以上传自己的 UTF-8 txt，或粘贴三章以上文本。

点**解析**。这步**纯代码、不依赖 AI**：拆章节段落，给每段生成**稳定 ID**——同一段文本永远是同一个 ID；整篇还有一个**指纹**，用来防伪造和锚定校验。

点**运行分析**：抽出人物、地点，还有事件卡、冲突卡、钩子候选。注意 **人物地点 ID 由系统按名字确定性生成**，不让模型乱编。点**生成规划**：改编成 3 集短剧，每集每场都有目的、冲突、情绪转折，右上的**事件覆盖率是程序算的**。

点**生成剧本**。出来的是结构化 YAML：集 → 场景 → 有序 beats。关键在这——**每个 beat 都带 source_refs**，点右边任意 beat 就能定位到它依据的原文段落；质量报告里的覆盖率、引用数也都是**程序算出来的**。

剧本是**可编辑**的。我把一个引用改成不存在的 ID，点校验——它**不相信模型、只认校验**，立刻报错，并给出**精确到这条引用的路径**。改回去再校验，通过。

通过的 YAML 可一键导出 **YAML / JSON / 改编报告**。背后是确定性内核加多阶段 pipeline，配 Schema 设计文档和 **168 个测试**；接上任意 OpenAI 兼容 Key，就能把**任意**小说转成同样可校验的剧本。"

## 3. 必须出现的"证据点"（验收对照）

- [ ] 稳定段落 ID（如 `ch1_p1_df6f5806`）+ 整篇**指纹** `68d7c2e2e2ec7e59` → 可追溯 / 防伪造
- [ ] 人物/地点**确定性 ID**（如 `char_aadd69` / `loc_a31088`）→ 引用稳定
- [ ] 事件卡 `dramatic_function` 标签 + 规划**事件覆盖率 100%** → 不漏改关键剧情
- [ ] YAML 里的 **`source_refs`** + 点 beat **高亮对应原文**（追溯 Inspector）→ 可追溯
- [ ] **质量报告**（覆盖率 / 引用段落 / 无溯源场景）= 程序计算 → 可复核
- [ ] **编辑后校验 → 精确路径错误**（`INVALID_SOURCE_REF` + `episodes[…].source_refs[…]`）→ 可校验、防幻觉
- [ ] 校验通过 → **导出 YAML / JSON / 改编报告**
- [ ] （加分）Schema 文档 + 168 测试 + live 模式一句话

## 4.（可选 +40 秒）live 模式：按集并行生成进度补拍

> 这是本工具最新的体验亮点：生成阶段**按集并行**，前端**流式**展示进度，不再"点完按钮像卡死"。**只在 live 模式可见**（fixture 生成是瞬时的）。

**切换环境**（与主体二选一，需重启 dev）：
1. 在 `.env.local` 注释掉 `DEMO_MODE=fixture`，填入 `OPENAI_API_KEY=…`（可选 `OPENAI_BASE_URL` / `MODEL_NAME`）。
2. 重启 `npm run dev`。解析后右上角应显示 **"live 模式"** 徽章。

**录制（建议对生成段做时间压缩 / 加速）**：
- 粘贴一段自有 ≥3 章小说（或继续用 Demo），依次 **解析 → 运行分析 → 生成规划**（这两步各显示 **"正在调用模型… 已用 Ns"** 计时横幅，不再是灰按钮）。
- 点 **生成剧本**：中栏出现进度横幅——**"正在并行生成各集（每集独立校验）· 已用 Ns"**，下面每集一枚状态 pill：
  - 进行中（转圈）→ **第 N 集 ✓**（绿，该集已通过校验）；个别可能短暂显示 **重试中**（黄，模型未过校验在自动重试）。
  - 随后横幅切到 **"装配整剧 → 校验结构与溯源 → 即将完成"**，最后落到**校验通过**、右栏出现 YAML。
- 旁白："生成是**按集并行**的——三集同时生成、每集独立校验通过才打勾，所以这条进度是**真实**的，不是假的进度条。一两分钟后整剧装配校验通过，YAML 就绪。"

> ⚠️ live 输出随模型变化、单集会重试，整段约 1–2 分钟；录制时建议加速或剪掉等待。若网络/额度不稳，可只用 fixture 主体。

## 5. 录制小贴士

- 关掉浏览器扩展弹窗、通知，避免遮挡。
- 每步点击后停 1–2 秒，给观众看清左栏状态从"未运行"→变绿、右栏数字变化。
- 失败重录时优先 fixture 模式（确定性、可复现）。
- 终端那一格保持 `168 passed` 可见，给"工程可信度"一个落点。
